# Serial input repair: A-001 / L-4 / C-131

**Software-only change; native console, Tk and serial behaviour remain not tested. T-006 remains NOT AUTHORISED.** Codex (OpenAI), 9 November 2026, from main `d5469297ed7cf8a41ff11585d84e1f0e44575364`; GitHub reported no open pull requests before implementation. This is S-103/C-139/T-021. The separate meter-error work is not included in this branch's verification.

## What the defect was

The old msvcrt decoder interpreted literal U+00E0 (`à`) as the same prefix as an extended key, then performed a second synchronous character read. An isolated character suspended receive polling and deadline checks; a following lowercase `q` could be discarded as that supposed key's suffix. Waiting for another character, or merely adding another availability check, cannot determine prefix identity in that character stream. The 8 November audit and old verification records remain historical evidence of that implementation.

## Chosen input policy

Console input now uses complete Windows `INPUT_RECORD` events through documented `ReadConsoleInputExW` with `CONSOLE_READ_NOWAIT` (`0x0002`). Each loop removes at most 32 events in one call. It never reads a suffix, builds a partial character sequence, waits for another event, or falls back to a stream read. Literal Unicode, isolated surrogate units, function/navigation keys, focus, mouse and resize records cannot become TV actions. A pressed lowercase `q` with `VK_Q`, positive repeat count and no Alt/Ctrl/Shift/enhanced-key flags requests stop. Key-up and uppercase Q do nothing. Lock flags are allowed when the translated character is still lowercase q. Excess input remains queued for subsequent bounded polls; a later q is retained, not treated as a suffix.

Console metadata does **not** reliably identify paste: Microsoft's console clipboard implementation can synthesize full virtual-key, scan-code and key-down/up pairs from text. Therefore **all typed or pasted command letters are inert**, including exact lowercase command letters. Pasted q may request a safe stop. Rather than claim an unreliable paste detector, TV actions and owner observations use a small separate **mouse-only serial controls window**. The unchanged internal allowlist is b/m/o/e/c/d/r; button labels state their actual meaning. Only the current phase's action is enabled, plus Stop. There is no keyboard accelerator, default command or text widget. Button class, toplevel and global binding tags are removed; mouse press/release is handled explicitly. Space, Return, navigation, `<<Invoke>>`, typing and paste cannot activate a command button. Lowercase q in the control window also requests stop.

A matching press and in-bounds release in the same phase are required. A phase change clears pending/pressed intent; queued events are drained against the old phase before enabling the next action, so old input cannot become a fresh attestation or send. More than one completed action in one event turn is discarded. There is no action queue. Stop, window closure and callback failure clear pending actions and remain terminal. A partial press never waits; receive polling and deadline checks continue. Each GUI turn processes at most 32 nonwaiting Tcl events; exhausting that budget rejects the session as ambiguous instead of starving serial polling. Callbacks only latch intent. Console q is checked before GUI intent.

The loop still logs receive bytes before parsing, observes fresh bytes and time before each action, rechecks deadlines before writes and logs write intent/count. The exact five-frame allowlist and sequence, uncertain-outcome stops, byte/event caps, final receive drain and no-retry/no-reconnect/no-automatic-restore rules are unchanged. Port closure remains the final result's `closed` field. New `serial_controls_closed` evidence separately reports GUI closure; a failed control close rejects completion even if the port close returned successfully. A printed phase alone proves neither closure.

The armed serial command now additionally requires explicit `--control-x` and `--control-y` (nonnegative desktop coordinates, 0..32767). Tk and its exact local build are now prerequisites for T-006 as well as presentation. The code places an automatically sized ordinary window at those coordinates; it does not enumerate/select monitors or prove visibility, correct monitor placement, scaling, fit or native disappearance. The reviewed physical preparation must establish usable placement on LG and continued access to Stop/console q before authorisation. Do not discover coordinates by trial launches. Redirected stdin, no attached console, missing NOWAIT export/API failure, disabled processed console input or VT input mode reject setup; no fallback opens a stream. No console modes or signal handlers are changed.

## Sources actually consulted

Consulted as text on 9 November 2026, with same-vendor research assistance; no source examples executed:

- Microsoft [ReadConsoleInputEx](https://learn.microsoft.com/en-us/windows/console/readconsoleinputex), updated 25 July 2022: documented dynamic Kernel32 `ReadConsoleInputExW` export, ABI and NOWAIT return even with no events; no peek/read race. [INPUT_RECORD](https://learn.microsoft.com/en-us/windows/console/input-record-str) and [KEY_EVENT_RECORD](https://learn.microsoft.com/en-us/windows/console/key-event-record-str), field layout, event type, Unicode/VK separation and processed Ctrl+C. [GetConsoleMode](https://learn.microsoft.com/en-us/windows/console/getconsolemode), processed and VT input modes.
- Microsoft Terminal source at `cbc857bdf7749981890c5b561ee44ea31948bfb1`: [Clipboard.cpp](https://github.com/microsoft/terminal/blob/cbc857bdf7749981890c5b561ee44ea31948bfb1/src/interactivity/win32/Clipboard.cpp), TextToKeyEvents calls CharToKeyEvents for paste; [EventSynthesis.cpp](https://github.com/microsoft/terminal/blob/cbc857bdf7749981890c5b561ee44ea31948bfb1/src/interactivity/base/EventSynthesis.cpp), CharToKeyEvents/SynthesizeKeyboardEvents creates ordinary VK/scan/down/up records. This demonstrates why event metadata alone is not a paste barrier; it is not identification or validation of the owner's installed host.
- Tcl/Tk [bind 8.6](https://www.tcl-lang.org/man/tcl8.6/TkCmd/bind.htm), binding tag order and break; [button.tcl core-8-6-branch](https://github.com/tcltk/tk/blob/core-8-6-branch/library/button.tcl), Space/Invoke and mouse class bindings. The implementation removes class/global tags instead of trusting a character filter. [Tcl_DoOneEvent](https://www.tcl-lang.org/man/tcl8.6/TclLib/DoOneEvent.htm), DONT_WAIT flag.
