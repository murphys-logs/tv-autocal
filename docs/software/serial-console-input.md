## What the defect was

The old msvcrt decoder interpreted literal U+00E0 (`à`) as the same prefix as an extended key, then performed a second synchronous character read. An isolated character suspended receive polling and deadline checks; a following lowercase `q` could be discarded as that supposed key's suffix. Waiting for another character, or merely adding another availability check, cannot determine prefix identity in that character stream. The 8 November audit and old verification records remain historical evidence of that implementation.

## Chosen input policy

Console input now uses complete Windows `INPUT_RECORD` events through documented `ReadConsoleInputExW` with `CONSOLE_READ_NOWAIT` (`0x0002`). Each loop removes at most 32 events in one call. The ABI uses explicitly sized Windows types (BOOL 32 bits, WORD/UTF-16 code unit 16 bits, DWORD 32 bits and pointer-sized HANDLE), so host wchar_t/long widths cannot change the fake record layout. It never reads a suffix, builds a partial character sequence, waits for another event, or falls back to a stream read. Literal Unicode, isolated surrogate units, function/navigation keys, focus, mouse and resize records cannot become TV actions. A pressed lowercase `q` with `VK_Q`, positive repeat count and no Alt/Ctrl/Shift/enhanced-key flags requests stop. Key-up and uppercase Q do nothing. Lock flags are allowed when the translated character is still lowercase q. Excess input remains queued for subsequent bounded polls; a later q is retained, not treated as a suffix.

Console metadata does **not** reliably identify paste: Microsoft's console clipboard implementation can synthesize full virtual-key, scan-code and key-down/up pairs from text. Therefore **all typed or pasted command letters are inert**, including exact lowercase command letters. Pasted q may request a safe stop. Rather than claim an unreliable paste detector, TV actions and owner observations use a small separate **mouse-only serial controls window**. The unchanged internal allowlist is b/m/o/e/c/d/r; button labels state their actual meaning. Only the current phase's action is enabled, plus Stop. There is no keyboard accelerator, default command or text widget. Button class, toplevel and global binding tags are removed; mouse press/release is handled explicitly. Space, Return, navigation, `<<Invoke>>`, typing and paste cannot activate a command button. Lowercase q in the control window also requests stop.

A matching press and in-bounds release in the same enabled phase are required for an action. Startup, phase changes and a full 32-event batch discard pending/pressed action intent and disable action buttons. Subsequent polls each drain at most 32 nonwaiting Tcl events; **ordinary window/redraw traffic does not abort the session**. Only a poll observing an empty event queue re-enables the current action, and a fresh click is then required. More than one completed action in one ordinary event turn is discarded; there is no action queue. The latest phase wins while draining, and stale clicks cannot become fresh attestations or sends. Widget states are configured only when they actually change, avoiding constant redraw requests.

Stop, q, window closure and callback failure remain terminal; Stop acts on left-button press without depending on a later release or phase. Callbacks only latch intent. Console q is checked before GUI intent. A partial press or ongoing GUI backlog never waits inside input handling, so serial receive and deadline work continues between bounded turns; an endless backlog can reach the existing session deadline. Before opening the port, the runtime requires startup quiescence within at most 100 such polls, checking q each time and pausing 10 ms between unsettled polls. Failure/cancellation prevents a port open; initial serial silence is still measured only after completed open. This is a fixed work allowance, not a guaranteed wall-clock duration or evidence of adequate native startup timing. The native startup/event/focus/fit gate remains explicit in T-006.

The loop still logs receive bytes before parsing, observes fresh bytes and time before each action, rechecks deadlines before writes and logs write intent/count. The exact five-frame allowlist and sequence, uncertain-outcome stops, byte/event caps, final receive drain and no-retry/no-reconnect/no-automatic-restore rules are unchanged. Port closure remains the final result's `closed` field. Operation failures retain their exception type and at most 256 message characters in private `serial_failure` evidence and the stop reason. New `serial_controls_closed` evidence separately reports GUI closure; a failed control close rejects completion even if the port close returned successfully. A printed phase alone proves neither closure.

The armed serial command now additionally requires explicit `--control-x` and `--control-y` (nonnegative desktop coordinates, 0..32767). Tk and its exact local build are now prerequisites for T-006 as well as presentation. The code places an automatically sized ordinary window at those coordinates; it does not enumerate/select monitors or prove visibility, correct monitor placement, scaling, fit or native disappearance. The reviewed physical preparation must establish usable placement on LG and continued access to Stop/console q before authorisation. Do not discover coordinates by trial launches. Redirected stdin, no attached console, missing NOWAIT export/API failure, disabled processed console input or VT input mode reject setup; no fallback opens a stream. No console modes or signal handlers are changed.
