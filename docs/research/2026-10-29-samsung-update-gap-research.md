**P11 and P3 describe different procedures.** P11's USB step 7 associates automatic start with connecting a flag-associated USB drive; its unzip section says the update folder (example T-KTM2DEUC) and `SWU_AUTO_FLAG` should be present after extracting the download. Thus the generic example describes a flag accompanying the downloaded package, not necessarily a separately created flag. P3 p. 4 instead tells the reader to store the flag, insert the image/flag media and reboot before the stated 3–5-minute start delay; it does not say whether that flag was bundled or separately obtained. P11 mentions no reboot or delay at that step, but that omission is not proof of immediate insertion-triggered updating on every build. These are different-model/region accounts, not an established contradiction about the same firmware. This English paraphrase is Codex's source interpretation; P11's literal `AUTO_FLAG` wording and named `SWU_AUTO_FLAG` are not treated as an implementation specification.

Whether the published **T-JZMDEUC.zip (1270.1)** actually includes `SWU_AUTO_FLAG` is **unknown**: the firmware archive was not downloaded or inspected. P5/P6's ordinary USB instructions do not resolve that content or trigger question. No package download, storage inspection, insertion or reboot is added by this research.

Other regional update pages were screened. Forum posts, user reports, community-hosted attachments and third-party explanations are excluded from the evidence. Search-result snippets were leads, not proof.

## Consequences for the reviewed method

**No gap is marked closed by this research.** The source evidence for information-only version display is stronger, but the current [conditional passive-entry rule](../tests/T-003-samsung-update-evidence.md#future-collection-boundary) still controls. Contact Samsung remains an information-view candidate requiring its own applicable basis; it supplies no automatic-update/pending state.

The USB flag pathway means that network Auto update and connectivity cannot be assumed to describe every update route. This is a source-based limitation for a future exposure argument, not an instruction to inspect storage, read flags, remove media, reboot, wait five minutes or initiate an update. The guide's claimed behaviour is **not tested** on the owner's equipment.

The 60-second acceptance interval cannot be used as a restart-protection window. A finite documented delay for one update route cannot clear an open-ended outstanding wait or establish that no process is already underway. The separate 1–2-minute startup advice is not evidence of background update activity; P8's at-least-10-minute duration is not an upper bound. None supplies a protection window for the 60-second discovery interval or its potentially longer wait. No elapsed waiting period is adopted as evidence of safety. Existing Windows, CEC, registry, isolation, identity, freshness and authority gates remain separate; the owner-check exemption and no-menu-during-outstanding-attempt rule are unchanged.

## Narrow next primary evidence to seek

The useful next evidence is a written, firmware-specific Samsung engineering/support explanation, with its date, exact model, firmware and route scope. The questions are:

1. For **UE49KS7000UXXU / T-JZMDEUC-1270.1**, does entering Contact Samsung or Software Update initiate any server connection, media search, queued update or other state change before an explicit update action? What starting conditions and prompts matter? After Update Now, is there a separate confirmation on this build, or can installation begin without one?
2. Is there a documented information-only way to distinguish no queued/downloaded/deferred update from an installed version display? What does that indication cover and leave out?
3. What happens to already staged/downloaded packages or deferred restarts when Auto update is Off or Internet is unavailable? Are network firmware, USB flag updates, Smart Hub, app and game mechanisms independent?
4. While the TV remains on the same HDMI desktop, what starts download, installation, prompts/overlays and restart? Can the TV restart without a further owner action, including after a prior reboot or during a prolonged wait? Does P3's USB flag description apply to this build? Does the published T-JZMDEUC-1270.1 USB package include `SWU_AUTO_FLAG`, and does this build trigger flag-based updating on insertion, on reboot, or both? What do the documented post-power-on availability waits mean for this build?

These are a documentary research brief, not a message sent to Samsung or an equipment procedure. An applicable answer could support a later tracked amendment; it must not be paraphrased into a guarantee broader than its conditions. If Samsung cannot provide the semantics, retain the unknowns and consider a separately scoped reviewed evidence plan; do not silently weaken the gate or invent a source guarantee.

## Research boundary and reproducibility

The search covered Samsung's exact-model UK listing/manual, the listed T-JZMDEUC family guide, UK version/update articles, regional automatic-update explanations, app/game update references and Samsung Developer firmware/status results. Targeted terms included passive/version views, pending/already-downloaded/staged updates, cancellation/Off semantics, firmware family/version, standby/background timing and USB auto flags. This was a bounded public-document search, not an exhaustive claim about all Samsung material.

The web tool could read the HTML articles but not the guide PDF; successful shell HTTPS retrieval supplied the guide and fresh e-Manual. Full HTML downloads confirmed P1's embedded file metadata. Source PDFs/HTML stay outside Git; only citations, identities and this analysis are proposed for review. No firmware package, executable, vendor application or calibration data was downloaded or run. No private session record was read or edited; no settings/registry/TV/meter/receiver/network inspection, installation, reset or physical experiment occurred. Public website retrieval is the only network activity.
