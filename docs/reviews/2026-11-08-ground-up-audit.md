### A-001 — Known console defect can suspend serial polling and consume quit

**P2, demonstrated software defect, high confidence; existing L-4, not a new discovery.** [serial_tool.py:324](https://github.com/murphys-logs/tv-autocal/blob/bcaf3d38ef03dca3b1607e0cb36c09ee3ea8f2b2/tv_autocal_tools/serial_tool.py#L324) treats U+00E0 as a special-key prefix and calls `getwch()` again without checking another character is available. The synchronous loop cannot poll receives/deadlines while that call waits; a subsequent `q` is consumed. C-096/C-097 and the existing component guide disclose this correctly.

The new inert [audit reproduction](../../tests/audit_ground_up.py) calls this method using a fake console that raises on an empty read. Lone U+00E0 attempts the second read; U+00E0 then q consumes q; ordinary q returns. CPython v3.15.0 source and Python console documentation support the blocking contract. **No native keyboard/serial experiment occurred.** Preserve the physical hold. A focused follow-up should use an event-aware, nonblocking console interface, preserve special-key rejection and validate delayed input/cancellation across every session phase. Adding one `kbhit()` check alone does not resolve Unicode/prefix identity or pending-input semantics. This audit changes no runtime behavior.

### A-002 — Serial logging cannot establish lossless wire capture

**P3, demonstrated dependency behavior and documentation-precision correction, high confidence.** [serial_tool.py:319](https://github.com/murphys-logs/tv-autocal/blob/bcaf3d38ef03dca3b1607e0cb36c09ee3ea8f2b2/tv_autocal_tools/serial_tool.py#L319) opens pySerial 3.5; its [pinned Windows backend](https://github.com/pyserial/pyserial/blob/0e7634747568547b8a7f9fd0c48ed74f16af4b23/serial/serialwin32.py#L84) requests receive/transmit queue clearing during open and ignores the PurgeComm return value. Its `read()` at lines 262–301 calls `ClearCommError` at line 274 and obtains `ClearCommError` flags but does not return framing/overrun/parity information. The project's fake port does not model either behavior.

Consequently “no resets/flushes” is true only of explicit project calls; journal completeness cannot mean lossless wire evidence. This PR narrows the public guide; the source docstring remains byte-identical to the reviewed manifest after correction B1: post-open application-returned bytes are logged subject to caps and existing close/stall limitations. It does not assert actual byte loss on this adapter. If future operation requires detection of native line errors, define and implement that transport contract in a focused follow-up; do not infer it from passing mocks or `log_complete`.

## Implementation and test assessment

`tv_autocal/` contains a narrow protocol fixture, deterministic renderer, toy TV/meter/clock cycle and offline evidence composition. The toy controller can inspect hidden simulated state; the physical implementation cannot. `tv_autocal_tools/` adds independently armed presenter, one-child-invocation meter capture and manual five-command serial diagnostics. It does not connect them into an autonomous calibration engine. Missing optimisation, packaging, HDR and production recovery are declared scope gaps, not bugs in promised completed features.

The parser rejects malformed/duplicate results, warning/error markers, stderr, incomplete text, non-finite values and bad process status. Finite negative/zero XYZ remain explicitly diagnostic; a production calibration consumer must impose its own physically meaningful validity and uncertainty criteria. Output labels do not authenticate invocation, units or correction. Meter capture requires EOF and child exit; timeout/cancellation reject acceptance while supervision continues. This leaves an unbounded outstanding-child wait and unbounded native logfile, already disclosed. A-007 adds a missed cause: the child's own input/retry loop, not only a stalled driver. A safe forced driver recovery is not established, so no kill/restart was tested or recommended as fact.

Serial handling checks allowlists, partial writes, late/malformed/duplicate/unsolicited replies, failed logging, observation generations and closure. Commands are manual, at most five, with no retry. A failed setter may leave state unknown and prohibit automatic restore; an owner-observed normal-menu restoration plan remains necessary. Current deadlines are cooperative checks, not hard real-time watchdogs. Two seconds, 60 seconds and quiet intervals are policy choices, not measured settling or reply-correlation guarantees.

The tests have meaningful independent literals for packets/geometry and adversarial type/bounds/error cases. Containment guards replace native calls and rerun functional cases; those reruns are not additional distinct tests. Fakes assume successful Tk/native geometry, process and port interfaces and cannot reveal unmodelled dependency behavior such as A-002. Existing tests do not establish signal bit fidelity, exact TV control, actual child lifetime, repeatability, absolute accuracy or restoration. The separate audit probe exposes A-001 without asserting that a known defect is correct behavior in the regression suite.

Security/privacy inspection found no application network client, secret submission, downloaded-code execution, dynamic plugin loader or shell-form command path. Hardware mode requires explicit scoped attestations; these are syntax checks, not authenticated owner authority. Executable full paths and hashes avoid ordinary PATH substitution but do not defeat concurrent replacement or prove signer/source-build identity. Private journals use exclusive bounded local files, flush/fsync and stop-on-error; they are not a hostile-filesystem sandbox or a guarantee against disk failure. Receipt validation checks the supplied log's consistency, not live display ownership. No private device IDs, addresses, credentials or raw personal logs are added by this PR.

`requirements-hardware.txt` pins optional pySerial 3.5 but has no distribution hash/lock. No package metadata, installer, chosen production Python or project licence exists. Standard-library/Tk/pySerial source/licence inspection does not choose a licence for this project. Direct V3.5.0 source and Windows-archive inspection upholds the earlier overall AGPLv3 versus GPLv2-or-later instrument-subset distinction; the full build links AGPL libraries. The publisher's frontend interpretation is attributed, not adopted as a legal conclusion. Separate processes alone do not settle the project's distribution obligations. Correction-data permissions likewise need checking for the chosen files and distribution model. These are Q-002/Q-003 release dependencies. No install or dependency upgrade was performed, and no known-vulnerability-free claim is made.
